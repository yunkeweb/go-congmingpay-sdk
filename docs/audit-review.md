# SDK 审查处理记录

日期：2026-11-12。审查基于外部测试工程的 `audit/sdk-remediation.md`、当前 SDK 源码及本地模拟测试。本文记录 SDK 侧的取舍，不将外部审查中的实测记录视作完整平台协议，也不声称重新完成了真实交易验证。

| 项目 | 判断与处理 |
| --- | --- |
| R01 日志 | 部分采纳。默认打印、默认不脱敏是既定使用契约，保留；不加入强制敏感字段名单、默认静默、元数据默认模式或正文开关。修复用户配置字段无法匹配 JSON 中 URL 查询参数的问题。非 JSON、自由文本及 URL 非查询部分的处理由使用者的 Hook 决定。 |
| R02 HTTP 错误 | 采纳。扩充现有 `HTTPError`，保留有界原始正文、大小截断标记、路径、选定诊断头和读取错误链；关闭日志也可取得。不自动重试，不把业务 fail 改为技术 error。 |
| R03 响应验签 | 规则确认前暂缓。普通响应及分账回退回调缺少可确认的签名字段范围和固定样例，不能套用请求算法。现有回调字段的认证范围继续以 README 和实现为准，Raw 不表示所有字段均已认证。 |
| R04 完整响应 | 采纳增量工具。保留 `Response` / `Result.Raw`，新增 `Decode` 供调用方声明需要的结构，不为全部端点复制一套响应 DTO 或方法。 |
| R05 类型读取 | 采纳。新增 `StringField` 和 `FieldTypeError`，区分缺失、空字符串、JSON null 和其他类型，保留字符串 `"null"`；原有快捷字段不变。 |
| R06 参数校验 | 认可协议边界，补文档。本次不增加未经确认的金额、枚举、URL 或业务状态限制；现有少量路径条件暂保留，未来规则增加时再评估私有校验归属，不为移动代码引入校验框架。 |
| R07 文档与覆盖 | 采纳可确认部分。说明订单标识、错误语义、超时与重试边界，补专属字段读取例子及本地回归。外部实测的平台行为仅是特定订单的观察，不提升为 SDK 通用规则。 |

`Decode` 是标准 JSON 解码便利方法，不是严格 schema 校验器：nil 响应报错，目标需为非 nil 指针；JSON null、缺失字段和部分填充遵循标准库行为。字段级 Raw 保留值和 JSON 类型，不承诺恢复完整 HTTP 正文布局。

本次验证使用合成报文和本地 Transport / TLS 服务，覆盖 HTTP 429 的 JSON 与非 JSON 正文、4 MiB 边界、部分读取失败、context 错误链、响应字段类型和大数、URL 查询参数脱敏及原始返回值隔离。测试中的订单号、域名和 token 均为合成值；不调用真实资金接口，不将本地通过等同于全平台成功路径已验证。

普通响应验签后续需要的平台材料：各端点或版本的适用范围、参与字段及顺序、值编码、缺失与 null 处理、签名大小写、缺失签名策略，以及可重复验证的完整响应与签名样例。取得这些资料后再实现和验证。
